# 「热门实测」第 1 期（x01） 需求单：AI 看 K 线（交给 AI 编程助手的原始需求）

> 这份需求单就是「热门实测」第 1 期（x01） 发给 AI 的提示词。「热门实测」是新系列，不占主系列「一期一个策略」的期号，内部编号 `x01`。流程沿用前几期：规则写死后才跑，看过结果不改主规则；看完结果才试的东西放进「变体」，照实报、不当结论。

## 要回答的问题
网上流传：一个开源的 K 线基础模型（Kronos，arXiv 2508.02739，代码 github.com/shiyu-coder/Kronos，MIT 许可），「给它看一张图，它就画出市场接下来往哪走，是一把带概率的扇形路径」。普通人照这个说法拿开源的小模型去用，明天涨跌猜得准吗？拿来交易能不能赚钱？

## 模型和环境
- 模型：`NeoQuasar/Kronos-small`（2,470 万参数，上下文最长 512 根），分词器 `NeoQuasar/Kronos-Tokenizer-base`。用官方代码，不改它的任何文件；代码不放进本仓库，按相对路径 `../third_party/Kronos` 引用，可用环境变量 `KRONOS_DIR` 改。
- 只用 CPU。权重缓存好以后离线跑（`HF_HUB_OFFLINE=1`）。
- 官方 `predict` / `predict_batch` 的 `sample_count` 会把多条路径取平均、只返回一条。要拿「一把路径」，把同一个窗口重复 N 次放进 `predict_batch`，`sample_count=1`。
- 每天单独设随机种子（由「种子号 + 标的 + 日期」算出），任何一天单独重跑结果都一样，可以断点续跑。每天的预测缓存到 `results/x01/`，后续统计只读缓存。

## 训练截止日（全片的关键）
论文写明：预训练数据截止 2024 年 6 月，所有测试从 2024 年 7 月开始。所以：
- **考题段（没见过）**：预测目标日 2024-07-01 至 2026-10-02。
- **对照段（训练期以内，可能见过）**：预测目标日个数与考题段相同，最后一天是 2024-06-28。我们不知道训练集具体包含哪些标的，只能说「可能见过」。

## 主规则（必须严格按这个写）
1. 每个交易日 t 收盘后，取截至 t（含 t）的最近 400 根日线：开、高、低、收、成交量（复权价）。
2. 预测 t+1 一根 K 线，32 条路径，温度 T=1.0，top_p=0.9（官方 README 的默认值），top_k=0。
3. 记下：32 条路径收盘价的均值、P(涨) = 收盘价高于 close_t 的路径比例、路径收盘价的 10/50/90 分位。
4. 交易：P(涨) > 0.5，t+1 开盘持有 SPY；否则空仓。空仓资金按 3 个月国债利率计息（和前几期一样）。单边 5 个基点。
5. 基准：买入持有（同一天开始、同样扣成本）；「天天猜涨」就是买入持有。

## 标的
SPY 是主角。QQQ、IWM、TLT、GLD 用来「换一个东西试试」，也用来算五个标的之间的横截面 RankIC。都只是数据样本，不是推荐。

## 要算的指标（两段各算）
1. **方向命中率**：路径均值相对 close_t 的方向 vs 实际 close_t→close_{t+1} 的方向。实际涨跌为 0 的天不计。和三个基准比：50%（扔硬币）、天天猜涨、「明天跟今天一样」（今天涨就猜明天涨）。给 95% 置信区间（Wilson）、对 50% 的精确二项检验、和两个基准的配对检验（只看两者猜得不一样的天）。
2. **IC / RankIC**：每个标的的时间序列相关（预测收益 = 路径均值 / close_t − 1，实际收益 = close_{t+1} / close_t − 1）；五个标的每天的横截面 RankIC 再取平均（和论文口径更接近）。
3. **P(涨) 的校准**：按 P(涨) 分桶（0–0.3、0.3–0.4、0.4–0.5、0.5–0.6、0.6–0.7、0.7–1），看每个桶实际涨了多少。
4. **扇形区间覆盖率**：实际收盘落在 10–90 分位之间的比例，应接近 80%。
5. **均值回拉检查**：官方代码用 400 根窗口的均值和标准差做归一化。算预测收益和 z = (close_t − 窗口收盘均值) / 窗口收盘标准差 的相关；同时算实际收益和 z 的相关。前者明显为负、后者接近 0，说明预测在往窗口均值拉，是归一化带来的，不是看懂了市场。
6. **交易规则**：年化、波动、夏普、最大回撤、交易次数、持仓比例，和买入持有比。另算一个「收盘价成交」的理想版本（用 close_t 出信号又在 close_t 成交，**做不到，只当上限**）。

## 复现「测试模式」
1. 按规则定日期，不挑：数据最后 20 个交易日藏起来，用之前的 400 根预测 20 天，32 条路径的扇形和实际走势放一起。这张图是画面素材。
2. 在考题段从第一天起每隔 20 个交易日做一次同样的 20 天预测，统计：实际走势有多少天落在扇形 10–90 分位里；「看起来像」= 20 天里至少 80% 的天落在扇形里（事先定）；终点方向对不对；终点误差。用来说明单张图不能说明问题。

## 必须带的检查（写进 results.json）
1. 两套独立引擎对账（`checks.reconcile`）。
2. 未来函数检查：挑考题段第一天、中间一天、最后一天，把 t 之后的价格和成交量全部乘上随机数，真跑一次模型，t 的路径必须完全不变，也必须和缓存一致。
3. 独立复算：绕开引擎和策略函数，另写一本现金 + 股数的账，最终倍数和交易次数要对上；命中次数从缓存的原始路径用纯 Python 再数一遍。
4. 三个随机种子（0、1、2，SPY 考题段），看结论稳不稳，并报三个种子信号一致的天数比例。
5. 路径数 8 / 32 / 64：SPY 考题段用 64 条路径跑一次，取前 8、前 32、全部 64 条。主结果用前 32 条。
6. 成本：0、2、5、10、20 个基点。
7. 阈值 0.5 / 0.55 / 0.6 × 路径数 8 / 32 / 64 的网格，**标「看完结果才试」，不当结论**。
8. 考题段前后两半分开看。
9. 「2010 年前后两段」不适用：本期的分界是训练截止日，用「训练期以内 vs 以外」代替。
